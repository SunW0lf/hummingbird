# Changelog

This records meaningful releases and changes, not a raw Git log.

## Unreleased — Phase 2: Read-Only Commons

- Resolved `OQ-GOVERNANCE-DECISION-PROCESS` and `OQ-GOVERNANCE-STEWARD-SCOPE` for the C0 working institution. Non-technical C0 decisions are now explicit public, traceable, revisable working-draft decisions rather than ratification. Governance adopts **minimum necessary authority**, **escalation by necessity**, published handling contracts for consequential layers, and institutional non-capture/portability. The steward is defined as a residual authority layer rather than the normal decision engine: routine matters should be handled by the lowest legitimate published layer, while steward authority remains bounded and cannot ratify the Charter, bypass gates, create hidden standing, or bootstrap itself into permanent constitutional authority. Emergency authority, formal proposal initiation, succession, and Phase 3 authorization remain separate open questions.
- Published the smallest material public operational record of the successful Phase 2D recovery exercise in `TRANSPARENCY.md`. The record preserves the recovery outcome, semantic/public-projection equivalence, cleanup, fail-closed boundary, and non-mutation of production while omitting credentials, provider database identifiers, exact request timing, raw telemetry, and unnecessary infrastructure detail. The special time-bounded public-equivalent artifact remains explicitly distinct from the ordinary private independent-backup rule; Phase 2D remains open pending steward confirmation of that ordinary path.
- Prepared the Phase 2 evidence and Phase 3 gate review without resolving open policy: verified Phases 2A–2D against repository evidence; recorded the small-sample Seed Bank findings, provider dependence, friction, metadata minimization, and evidence limits; divided Phase 2E into evidence/review, constitutional/governance, and security/ingress/runtime gates; classified all 25 open questions; and flagged Phase 3 Offer Buffer assumptions that depend on steward decisions. No Phase 3 capability or authorization was added.
- Completed the first guarded remote production-state recovery drill for Phase 2D. Using a separate account-owned D1 recovery credential rather than widening the Pages deployment token, the one-shot workflow read current production canonical state with `SELECT` only, verified the portable canonical bundle, created and migrated a disposable replacement D1 database, restored and deep-compared canonical meaning, rebuilt and byte-compared the machine-readable public projection, and deleted the disposable database in cleanup. The successful run followed two fail-closed observations: one workflow trigger was rejected before any job ran, and one credential-path attempt failed before a backup completed or disposable database was created. Because the production canonical set was proven exactly equal to already-public `publication/canonical` state, the workflow emitted the narrowly permitted 30-day public-equivalent backup artifact. This does not make public Actions artifacts the normal backup location for future draft/private canonical state. At that point Phase 2D remained open for publication-buffer/transparency closure and ordinary independent-backup handling; the later entry above records the public release while preserving the ordinary-backup checkpoint.
- Began the substantive Phase 2D recovery slice: replaced the original Phase 0 `backup`/`restore` no-ops with a storage-independent canonical backup bundle, per-record and bundle SHA-256 verification, guarded restore tooling, and CI proof that canonical records can be exported from one migrated local D1 and restored into a separately migrated empty D1 with deep semantic equality. Restore refuses non-empty targets; the general-purpose restore command does not write to remote D1. Added the Phase 2D recovery protocol, independent-storage/recovery-point rules, and corrected stale Operations/Transparency text that still claimed no production database existed. The remaining Phase 2D work is to publish the successful recovery outcome through the bounded publication-buffer/transparency path and keep the normal independent-storage rule explicit for future non-public canonical state.
- Accepted [ADR 0016](docs/decisions/0016-offers-and-the-offer-buffer.md), defining **offer**, **offer delivery options**, **Offer Buffer**, and **consideration** as the future Phase 3 participation vocabulary. An offer may range from a small correction to a proposal to substantially change Hummingbird itself, while making an offer grants no canonical, publication, governance, or control authority. Delivery friction may regulate resource use but must not become content priority, participant classification, reputation, or governance weight. The design is public and tested while `/offer`, `/api/offer`, capability issuance, and all Phase 3 runtime remain undeployed.
- Accepted [ADR 0015](docs/decisions/0015-standards-based-representation-discovery-and-provenance.md) and strengthened the public Decisions surface with source-level provenance: each public ADR exposes its canonical source path, the Git commit that last changed that source, an exact SHA-256 digest of the canonical Markdown, the separate site build commit, immutable source linkage, raw Markdown alternate representation, and a machine-readable provenance index. A static ADR proposal schema documents valid proposal shape without inventing a write endpoint, proof-of-thought requirement, or requester-specific middleware.
- Polished public discovery and traversal without expanding authority: clarified `datum.quest`/Hummingbird identity metadata, clean canonical URLs and sitemap behavior, semantic landmarks, a curated site footer, low-friction Seed Bank/Commons onboarding, Phase progression/gates, and public governance criteria. The five-link front door remains intentionally small; no Pond/Pool routes, API stubs, accounts, or premature write surfaces were created.

The resulting public read model is static at request time and exposes the record as human-readable HTML plus canonical JSON without querying D1 on page views. Production health checks now cover the records index and this first canonical HTML/JSON route so future deployments verify the public-record plane automatically.
- Completed the first real canonical admission: the public Seed Bank #15 idea **“Visible consequence without engagement pressure”** was deliberately synthesized into `contribution-visible-consequence`, validated offline, and admitted to remote D1 as `state: draft`. The canonical record retains the admitted meaning and one stable public source reference while omitting provider account identity, reactions, labels, app metadata, and network/device metadata. Admission did not publish the record or grant governance status.

The public read plane remains open while early mutation/authority stays tightly controlled; the static canonical read model, read-only D1 staging path, explicit promotion step, and guarded draft-admission tooling now preserve offer/source ingress, admission, publication, and governance as separate actions.
