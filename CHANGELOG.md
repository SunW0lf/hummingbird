# Changelog

This records meaningful releases and changes, not a raw Git log.

## Phase 2 — Read-Only Commons (in progress)

- Accepted [ADR 0023](docs/decisions/0023-narrow-core-offering-arrive-leave-carry.md) and narrowed the core product promise to **Arrive / Leave / Carry**: open origin-neutral public reading, bounded contribution without automatic canonical/public/governance status, and portable public artifacts that can be carried elsewhere. Social-network mechanics, general chat, reputation/identity systems, general agent workspaces, and persistent rooms/guilds/games are no longer current core roadmap goals merely because earlier designs explored them; those ideas remain inspectable design history or Lab material and require a separate explicit decision to return to scope. The Mission, Project, agent guidance, homepage, and commons explainer were refactored around the narrower model. This scope decision does not rename Hummingbird, authorize Phase 3, expand `/offer`, or resolve any participant-rights, governance, security, or runtime open question.
- Closed **Phase 2E.1 — Evidence and Phase 2 review** without opening Phase 3. The upgraded private offer-review → `canonical-candidate-v1` path was operationally verified end-to-end, including an empty-inbox run that produced an empty `candidate_only` manifest rather than invented material. [ADR 0022](docs/decisions/0022-phase2e1-review-gate-dispositions.md) records the four Phase 2 review-gate dispositions: long-term steward succession is deliberately deferred to Phase 2E.2 under continuity-without-entrenchment constraints that separate custody, stewardship, and governing authority; Phase 2 adopts a bounded incident lifecycle whose containment authority comes only from already-published powers; monitoring is now based on observable capabilities, freshness, data minimization, and separation of observation from authority, with a scheduled plain-HTTP public-read check added for degradation independent of deploys; and credential rotation is replaced by a risk-based lifecycle with immediate revocation triggers and a 180-day Phase 2 ordinary review/maximum-lifetime baseline for the current deployment token. The deferred succession, mature incident-response, monitoring/alerting, and credential-lifecycle questions remain `OPEN` for Phase 2E.2/2E.3; all eight Phase 3 blockers remain binding, and no automatic canonical mutation or Phase 3 authority was created.
- Closed Phase 2D after the ordinary independent private-backup checkpoint was completed: a retained encrypted canonical bundle was independently retrieved from the private backup repository, decrypted with the steward-held `age` identity outside GitHub/Cloudflare, and validated with the repository recovery tooling. The same validated read-only export path is now scheduled daily while retaining the manually confirmed trigger; only ciphertext plus its transport checksum enter the private repository. This closes the durability milestone without opening Phase 3 or changing canonical admission authority.
- Added the first automation layer between temporary evidence and canonical admission: `canonical-candidate-v1` is a portable, explicitly non-canonical candidate envelope with machine-validatable source/derivation metadata, a reference fixture, CI validation, and deterministic draft-record extraction. Candidate envelopes are hard-coded as `candidate_only`, reject receipt secrets/provider identity fields, and reuse the existing draft-admission validator without remote access. They may be prepared automatically, but cannot admit, publish, or grant governance status to themselves.
- Prepared the ordinary Phase 2D private-backup path: a manually confirmed workflow now exports canonical production state read-only, validates the portable bundle, encrypts it to a steward-held `age` recipient, removes runner plaintext, and sends only ciphertext plus a transport checksum to the dedicated private `SunW0lf/hummingbird-backups` repository using a destination-scoped credential. Phase 2D remains open until a real run is independently retrieved, decrypted, and validated; the decryption identity remains outside GitHub and Cloudflare.
- Verified the private Phase 2E offer review path: the separate restricted companion repository completed a manual D1 read and produced a one-day `offer-review` artifact. The public hourly observer still exposes only a pending count and boolean; each future run must be checked for success and freshness before reporting the inbox clear. This closes the setup gap recorded below, but does not make offer contents public or grant accepted offers canonical or governance status. Phase 2D still awaits confirmation of ordinary independent private-backup handling, and Phase 3 remains gated.

The offer page and `llms.txt` document the existing URL-encoded form and optional JSON response for authorized plain-HTTP clients without deploying a new API or granting new authority. Recorded the verified private review artifact path and the separate outstanding search-index/host-alias checks; no offer contents or credentials were published.

- Accepted [ADR 0017](docs/decisions/0017-phase2e-experimental-ingress.md), [ADR 0018](docs/decisions/0018-phase2e-offer-pilot-runtime-and-data-boundary.md), and [ADR 0019](docs/decisions/0019-phase2e-offer-triage-and-review.md) for the bounded Phase 2E first-party offer experiment. - Resolved `OQ-GOVERNANCE-DECISION-PROCESS` and `OQ-GOVERNANCE-STEWARD-SCOPE` for the C0 working institution. Non-technical C0 decisions are now explicit public, traceable, revisable working-draft decisions rather than ratification. Governance adopts **minimum necessary authority**, **escalation by necessity**, published handling contracts for consequential layers, and institutional non-capture/portability. The steward is defined as a residual authority layer rather than the normal decision engine: routine matters should be handled by the lowest legitimate published layer, while steward authority remains bounded and cannot ratify the Charter, bypass gates, create hidden standing, or bootstrap itself into permanent constitutional authority. Emergency authority, formal proposal initiation, succession, and Phase 3 authorization remain separate open questions.
